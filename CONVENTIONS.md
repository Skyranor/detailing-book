# Оформление книги

Единый источник правды по оформлению markdown. При расхождении текста
главы с этим файлом прав этот файл. Специфика жанра (единицы измерения,
маркеры, работа с брендами) — в [system/prompts.md §9](system/prompts.md).

Проверяется механически:

```bash
npm run lint
```

Соглашения выведены не из вкуса, а из одного ограничения: **книга
читается на сайте**. Сайт — единственная среда, под которую пишется
текст. Отрисовка файла в GitHub и в превью редактора решений не
определяет: там смотрят исходник, а не читают книгу.

Из этого следует главное правило: приём допустим, если сайт превращает
его в оформление. Форма, которую сайт не разбирает, выйдет на страницу
сырым текстом — и читатель увидит мусорную строку.

Второе следствие — телефон. Значительная часть чтения идёт с экрана
шириной 360–430 точек. Схема шире 80 символов, таблица в семь колонок
и абзац на пятнадцать строк ломаются именно там.

Сайт собирается из этих же файлов и ничего в них не дублирует
([§11](#11-как-книга-превращается-в-сайт)).

## 1. Что сайт отрисовывает

| Приём | Что делает сайт | Вердикт |
| --- | --- | --- |
| Заголовки `##`, `###` | Раздел с цветной меткой по названию, оглавление справа | использовать |
| Таблицы GFM | Карточка с прокруткой, на телефоне — по строке на карточку | использовать |
| Блок ` ```text ` | Моноширинный блок с прокруткой | использовать |
| Абзац с `⚠️` в начале | Плашка предупреждения | использовать |
| Абзац с `**Пример.**` и родственниками | Врезка с меткой ([§4](#4-врезки)) | использовать |
| `![Подпись](/img/…)` | Фотография с подписью ([§5](#5-изображения)) | использовать |
| `<details><summary>` | Скрытый ответ упражнения | использовать |
| `[ПРОВЕРЬ TDS]`, `[СПОРНО]`, `[НЕ ОБЕЩАЙ КЛИЕНТУ]` | Цветная плашка в тексте | использовать |
| Ссылка `[главе 18](18-machines.md)` | Ссылка на страницу главы либо пометка «скоро» | использовать |
| Цитата `>` | Выделенный блок | использовать умеренно |
| Списки, в том числе `- [ ]` | Список, чек-боксы | использовать |
| Mermaid | ничего: сырой текст на странице | **не использовать** |
| GFM-алерты `> [!NOTE]` | ничего | **не использовать** |
| Сноски `[^1]` | ничего | **не использовать** |
| Контейнеры `:::note`, `:::tip` | ничего | **не использовать** |
| YAML-frontmatter | показывает как текст | **не использовать** |
| Ручное оглавление внутри главы | не нужно: колонка справа | **не делать** |

Метаданные главы живут не во frontmatter, а строками сразу под
заголовком:

```text
`Уровень: L2`
`Блок: мойка`
`Риск ошибки: средний`
`Предполагает знание глав: 4, 6, 7`
```

Форма этих строк значима: сайт разбирает их и показывает шапкой главы
(уровень, блок, риск, ссылки на нужные главы, время чтения). Пробелы,
двоеточие и обратные кавычки — как в примере.

## 2. Блоки кода

### 2.1. Тег обязателен у каждого блока

Безымянный ` ``` ` запрещён. Тег даёт возможность выбрать блоки
скриптом и не ломает отрисовку.

| Роль блока | Тег |
| --- | --- |
| Схема, диаграмма, разрез ЛКП, раскладка бокса, расчёт | `text` |
| Шаблон документа, формулировка для клиента, текст промта | `text` |
| Команда оболочки | `bash` |

Больше тегов в этой книге не нужно: исполняемого кода в ней нет.

### 2.2. Метаданные у фенса запрещены

Запрещены все формы: ` ```text title="…" `, ` ```bash showLineNumbers `.
Сайт их не показывает — первый токен идёт в подсветку, остальное
отбрасывается.

### 2.3. Фенс на нулевом отступе, вне blockquote и вне списка

| Форма | Что происходит |
| --- | --- |
| Фенс на нулевом отступе | правильно |
| Фенс внутри `>` | содержимое уезжает вместе с префиксами `> ` |
| Фенс внутри элемента списка | разметка списка рвётся, если отступ не выровнен по содержимому пункта |
| Фенс внутри `<details>` | безопасно |

Отсюда правило: нумерованный шаг, к которому прилагается схема или
расчёт, разрывается — текст шага, затем блок на нулевом отступе, затем
продолжение нумерации.

### 2.4. Ширина

Схемы в блоках `text` не шире **80 символов**. На телефоне блок шире
экрана прокручивается вбок, а в схеме значима каждая колонка: читатель
теряет правую часть и не понимает, что смотрит.

---

## 3. `<details>`

Формат:

```text
<details>
<summary>Эталонный ответ</summary>

Текст ответа.

</details>
```

Пустая строка после `</summary>` и перед `</details>` **обязательна**:
без неё markdown внутри не разбирается и выходит исходником.

Где применяется: ответ, который читатель должен получить сам, —
эталонный ответ экзамена, решение задачи из раздела «Практика».
Где не применяется: содержательный текст главы. `<details>` — способ
спрятать ответ, а не способ визуально сократить главу.

---

## 4. Врезки

Врезка — **один абзац**, начинающийся с жирного слова из закрытого
списка. Сайт превращает такой абзац в выделенный блок с меткой.

| Начало абзаца | Что это | Длина |
| --- | --- | --- |
| `**Пример.**` | Конкретная машина, конкретные числа, конкретный итог | 3–8 строк |
| `**Откуда цифра.**` | Чем измерено, на чём, сколько замеров, где перестаёт работать | 3–6 строк |
| `**Для новичка.**` | То, что мастер считает само собой разумеющимся | 2–5 строк |
| `**Для опытного.**` | Крайний случай, переучивающая цифра, граница приёма | 2–5 строк |
| `⚠️ ` в начале абзаца | Предупреждение | 1–4 строки |

Как это выглядит в файле:

```text
**Откуда цифра.** Диапазон 3–8 мкм за проход снят толщиномером
с точностью ±2 мкм на трёх донорских капотах: два японских мягких
лака, один немецкий твёрдый. По пять замеров на каждой панели до
и после. На твёрдом лаке нижняя граница ближе к 2 мкм, на свежем
перекрасе цифра не работает вовсе.
```

Врезка не заменяет подраздел: если материала больше абзаца, это `###`.
Расчёт после врезки выносится следом блоком ` ```text `.

Слово в начале врезки пишется точно как в таблице, с точкой. Другое
слово сайт не распознает, и абзац выйдет обычным текстом.

## 5. Изображения

```text
![Паутинка на чёрном лаке под точечным светом с 20 см](/img/05-swirls.jpg)
```

| Правило | Почему |
| --- | --- |
| Файлы лежат в `public/img/` | Сайт отдаёт их по адресу `/img/…`; путь в тексте — от корня, а не относительный |
| Имя начинается с номера главы: `05-swirls.jpg` | Видно, к чему относится, и файлы сортируются по книге |
| Подпись обязательна | Она отрисовывается под фотографией и объясняет, что именно смотреть |
| Ширина исходника 1200–2000 точек | Меньше — мыло на большом экране, больше — вес страницы |

Подпись «фотография риски» — плохая. Подпись «риска, не цепляющая
ноготь: дно видно, края скруглены» — хорошая: она говорит, на что
смотреть.

Изображение ставится там, где текстом научить нельзя: виды рисок
и голограммы, реакция железоудалителя, поведение света на дефектах,
раскладка бокса, состояния пада, шкала на приборе. Иллюстрация «для
красоты» не ставится.

---

## 6. Эмодзи и маркеры

Разрешены ровно три: ❌ ✅ ⚠️

Запрещены как замена им: ✓ ✔ ✗ ✘ ◆ ◇ ☑ ☒ — они не читаются голосом,
по-разному рендерятся в моноширинных шрифтах и не грепаются
единообразно.

Исключение: в `README.md` дополнительно допустимы 🟡 ⬜ ☐ — легенда
статуса глав и чек-боксы личного прогресса.

Псевдографика диаграмм (`─ │ ┌ ┐ └ ┘ ├ ┤ ▲ ▼ ◀ ▶`) эмодзи не является
и не ограничивается.

Текстовые маркеры книги — `[ПРОВЕРЬ TDS]`, `[СПОРНО]`,
`[НЕ ОБЕЩАЙ КЛИЕНТУ]` — пишутся как обычный текст, без эмодзи
и без цветовых пометок.

## 7. Ссылки и подвал навигации

**Отсылка на главу — ссылка на файл, а не текст «глава N».** Книга
построена на перекрёстных отсылках, и в виде текста эта конструкция
не работает как гипертекст.

| Откуда | Формат |
| --- | --- |
| Из соседней главы | `[главе 18](18-machines.md)` |
| Из `README.md` | `[главе 18](chapters/18-machines.md)` |
| Из `system/`, `revisions/`, `plans/` | `[главе 18](../chapters/18-machines.md)` |

Ссылка на ещё не написанную главу допустима: оглавление в `README.md`
полное по замыслу, а главы ссылаются вперёд постоянно. Линтер отличает
такие ссылки от битых по списку глав в `README.md`.

Плотность ссылок нормируется: внутри текста раздела — не больше трёх,
остальные собираются строкой «Куда дальше» в конце раздела. Ссылка
в середине предложения уводит читателя со страницы.

**Подвал главы** — последняя строка файла:

```text
[← 7. Безопасность](07-safety.md) · [Оглавление](../README.md) · [9. Оборудование →](09-equipment.md)
```

Порядок глав задаёт оглавление `README.md`, а не имена файлов. У первой
главы опускается левая ссылка, у последней написанной — правая: ссылка
из подвала ведёт только на существующий файл, иначе читатель попадает
в 404. Когда пишется следующая глава, правая ссылка предыдущей
дописывается тем же коммитом.

Линтер проверяет, что подвал есть (`footer-missing`) и что он никуда
не ведёт мимо файла (`link-broken`).

## 8. Диаграммы

ASCII — основной формат. Он грепается, даёт построчный diff при правках
и читается на любой ширине экрана до 80 символов. Mermaid не
используется: сайт его не отрисовывает.

Все ASCII-диаграммы помечаются ` ```text ` ([§2.1](#21-тег-обязателен-у-каждого-блока)).

---

## 9. Что решено не делать

| Приём | Почему нет |
| --- | --- |
| Mermaid, GFM-алерты, сноски, `:::note` | Сайт их не отрисовывает: выйдут сырым текстом |
| Frontmatter | Метаданные главы читаются из строк под заголовком |
| Ручной TOC внутри главы | Дублирует колонку разделов, устаревает при первой правке заголовка |
| Строки схем шире 80 символов | Ломаются на телефоне |
| Таблица шире пяти колонок | На телефоне не читается даже карточкой; режется на две |
| Таблица из двух колонок вместо абзаца | Механизм и причина в ячейку не помещаются |
| Врезка из нескольких абзацев | Врезка — один абзац; дальше это подраздел |
| Изображение без подписи | Читатель не знает, что смотреть |

## 10. Что проверяет линтер

```bash
npm run lint          # весь репозиторий
npm run lint -- --report       # отчёт без ненулевого кода возврата
```

| Правило | Что ищет |
| --- | --- |
| `fence-untagged` | безымянный ` ``` ` |
| `fence-unknown-tag` | тег вне списка `text` / `bash` |
| `fence-meta` | метаданные у открывающего фенса |
| `fence-in-quote` | блок кода внутри `>` |
| `fence-indented` | блок кода внутри элемента списка |
| `fence-unclosed` | незакрытый блок |
| `fence-wide` | строка блока `text` шире 80 символов |
| `emoji` | эмодзи вне разрешённого набора |
| `marks` | ✓ ✗ ● ◆ и родственники |
| `link-broken` | относительная ссылка на несуществующий файл |
| `image-missing` | изображение, которого нет в `public/` |
| `image-no-alt` | изображение без подписи |
| `callout-unknown` | абзац начинается с жирного слова, похожего на врезку, но не из списка §4 |
| `footer-missing` | у главы нет подвала навигации |
| `details-blank-line` | `<details>` без пустых строк вокруг содержимого |
| `frontmatter` | YAML-frontmatter в начале файла |

Ссылки на главы, объявленные в `README.md`, но ещё не написанные,
считаются запланированными и находкой не являются: они печатаются
отдельной строкой в сводке.

Не проверяются `CONVENTIONS.md` и `system/`: там внутри блоков лежат
тексты промтов и примеры запрещённых форм, и они обязаны оставаться
дословными.

## 11. Как книга превращается в сайт

Сайт не хранит текст. Он читает те же файлы и раскрашивает их при
сборке. Отсюда несколько форм, которые нельзя ломать «для красоты».

| Что в файле | Во что превращается на сайте |
| --- | --- |
| Оглавление в `README.md` | Левая колонка, обложка, порядок глав, кнопки «предыдущая / следующая» |
| Строки `` `Уровень: L2` `` под заголовком | Шапка главы: уровень, блок, риск, ссылки на нужные главы |
| `## Название раздела` | Раздел с цветной меткой; красная у «Безопасности», «Цены ошибки», «Разбора брака», зелёная у «Проверки» и «Практики» |
| `[ПРОВЕРЬ TDS]`, `[СПОРНО]`, `[НЕ ОБЕЩАЙ КЛИЕНТУ]` | Цветные плашки в тексте |
| Абзац, начинающийся с ⚠️ | Плашка предупреждения |
| Абзац, начинающийся с `**Пример.**` и родственников | Врезка с меткой |
| `![Подпись](/img/…)` | Фотография с подписью под ней |
| Таблица | Карточка с прокруткой; на экране уже 640 точек — по карточке на строку, с названиями колонок |
| Ссылка на ненаписанную главу | Не ссылка, а пометка «скоро»: читатель не попадает в пустоту |
| Подвал навигации главы | Убирается: его заменяют кнопки внизу страницы |
| `---` между разделами | Убирается: разделы уже разделены вёрсткой |
| ` ```text ` со схемой | Моноширинный блок с горизонтальной прокруткой |

Что из этого следует для того, кто пишет главы:

- **Строка главы в оглавлении `README.md` имеет значение.** Формат
  `| 9 | [Название](chapters/09-equipment.md) | ⬜ |`. Пока стоит ⬜,
  глава не открывается и все ссылки на неё показываются как «скоро».
  Меняете ⬜ на ✅ — глава появляется на сайте.
- **Названия разделов берутся из списка** мастер-промта
  ([prompts.md §1](system/prompts.md)). Придуманное своё название
  отрисуется, но без цветной метки.
- **Ничего не нужно делать руками для сайта.** Ни адресов страниц,
  ни оглавления внутри главы, ни картинок-заголовков.

Посмотреть, как глава выглядит на сайте, до публикации:

```bash
npm run dev
```

Проверка перед публикацией — линтер и сборка:

```bash
npm run lint
npm run build
```
