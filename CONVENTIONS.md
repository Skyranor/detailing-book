# Оформление книги

Единый источник правды по оформлению markdown. При расхождении текста
главы с этим файлом прав этот файл. Специфика жанра (единицы измерения,
маркеры, работа с брендами) — в [system/prompts.md §8](system/prompts.md).

Проверяется механически:

```bash
npm run lint
```

Соглашения выведены не из вкуса, а из одного ограничения: **один и тот же
файл главы читают в трёх местах** — на сайте книги, на GitHub и во
встроенном превью VS Code. Приём, который работает не везде, здесь
не используется: где-то он не отрисуется и покажется читателю как
мусорные строки.

Сайт собирается из этих же файлов и ничего в них не дублирует
([§9](#9-как-книга-превращается-в-сайт)).

---

## 1. Что рендерится где

| Приём | Сайт | GitHub | Превью VS Code | Вердикт |
| --- | --- | --- | --- | --- |
| Блок ` ```lang ` | да | да | да | использовать |
| Таблицы GFM | да | да | да | использовать |
| `<details><summary>` | да | да | да | использовать |
| Mermaid | нет | да | да | **не использовать** |
| GFM-алерты `> [!NOTE]` | нет | да | **нет** | **не использовать** |
| Сноски `[^1]` | нет | да | **нет** | **не использовать** |
| Контейнеры `:::note`, `:::tip` | нет | нет | нет | **не использовать** |
| YAML-frontmatter | нет | скрывает | показывает как текст | **не использовать** |
| Ручное оглавление внутри главы | не нужно: колонка справа | не нужно: панель Outline | не нужно: Outline | **не делать** |

Метаданные главы живут не во frontmatter, а строками сразу под
заголовком:

```text
`Уровень: L2`
`Блок: мойка`
`Риск ошибки: средний`
`Предполагает знание глав: 4, 6, 7`
```

Форма этих строк значима: сайт разбирает их и показывает шапкой главы
(уровень, блок, риск, ссылки на нужные главы, время чтения). Пробелы,
двоеточие и обратные кавычки — как в примере.

## 2. Блоки кода

### 2.1. Тег обязателен у каждого блока

Безымянный ` ``` ` запрещён. Незнакомый тег оба рендерера показывают
как моноширинный текст, поэтому тег ничего не портит, а даёт
возможность выбрать блоки скриптом.

| Роль блока | Тег |
| --- | --- |
| Схема, диаграмма, разрез ЛКП, раскладка бокса, расчёт | `text` |
| Шаблон документа, формулировка для клиента, текст промта | `text` |
| Команда оболочки | `bash` |

Больше тегов в этой книге не нужно: исполняемого кода в ней нет.

### 2.2. Метаданные у фенса запрещены

Запрещены все формы: ` ```text title="…" `, ` ```bash showLineNumbers `.
Ни GitHub, ни превью VS Code их не показывают — первый токен идёт
в подсветку, остальное отбрасывается. Приём распространён в Starlight,
VitePress и Docusaurus, но там его отрисовывает генератор.

### 2.3. Фенс на нулевом отступе, вне blockquote и вне списка

| Форма | Что происходит |
| --- | --- |
| Фенс на нулевом отступе | правильно |
| Фенс внутри `>` | содержимое уезжает вместе с префиксами `> ` |
| Фенс внутри элемента списка | GitHub разрывает список, если отступ не выровнен по содержимому пункта |
| Фенс внутри `<details>` | безопасно |

Отсюда правило: нумерованный шаг, к которому прилагается схема или
расчёт, разрывается — текст шага, затем блок на нулевом отступе, затем
продолжение нумерации.

### 2.4. Ширина

Схемы в блоках `text` не шире **80 символов**: иначе они переносятся
в превью VS Code и в мобильном GitHub, а в схеме значима каждая
колонка.

## 3. `<details>`

Формат:

```text
<details>
<summary>Эталонный ответ</summary>

Текст ответа.

</details>
```

Пустая строка после `</summary>` и перед `</details>` **обязательна**:
без неё GitHub не рендерит markdown внутри и показывает исходник.

Где применяется: ответ, который читатель должен получить сам, —
эталонный ответ экзамена, решение задачи из раздела «Практика».
Где не применяется: содержательный текст главы. `<details>` — способ
спрятать ответ, а не способ визуально сократить главу.

---

## 4. Эмодзи и маркеры

Разрешены ровно три: ❌ ✅ ⚠️

Запрещены как замена им: ✓ ✔ ✗ ✘ ◆ ◇ ☑ ☒ — они не читаются голосом,
по-разному рендерятся в моноширинных шрифтах и не грепаются
единообразно.

Исключение: в `README.md` дополнительно допустимы 🟡 ⬜ ☐ — легенда
статуса глав и чек-боксы личного прогресса.

Псевдографика диаграмм (`─ │ ┌ ┐ └ ┘ ├ ┤ ▲ ▼ ◀ ▶`) эмодзи не является
и не ограничивается.

Текстовые маркеры книги — `[ПРОВЕРЬ TDS]`, `[СПОРНО]`,
`[НЕ ОБЕЩАЙ КЛИЕНТУ]` — пишутся как обычный текст, без эмодзи
и без цветовых пометок.

## 5. Ссылки и подвал навигации

**Отсылка на главу — ссылка на файл, а не текст «глава N».** Книга
построена на перекрёстных отсылках, и в виде текста эта конструкция
не работает как гипертекст.

| Откуда | Формат |
| --- | --- |
| Из соседней главы | `[главе 18](18-machines.md)` |
| Из `README.md` | `[главе 18](chapters/18-machines.md)` |
| Из `system/`, `revisions/`, `plans/` | `[главе 18](../chapters/18-machines.md)` |

Ссылка на ещё не написанную главу допустима: оглавление в `README.md`
полное по замыслу, а главы ссылаются вперёд постоянно. Линтер отличает
такие ссылки от битых по списку глав в `README.md`.

**Подвал главы** — последняя строка файла:

```text
[← 7. Безопасность](07-safety.md) · [Оглавление](../README.md) · [9. Оборудование →](09-equipment.md)
```

Порядок глав задаёт оглавление `README.md`, а не имена файлов. У первой
главы опускается левая ссылка, у последней написанной — правая: ссылка
из подвала ведёт только на существующий файл, иначе читатель попадает
в 404. Когда пишется следующая глава, правая ссылка предыдущей
дописывается тем же коммитом.

Линтер проверяет, что подвал есть (`footer-missing`) и что он никуда
не ведёт мимо файла (`link-broken`).

## 6. Диаграммы

ASCII — основной формат. Он читается в исходнике без рендера,
грепается и даёт построчный diff при правках. Mermaid допустим
для нового чистого графа, но не для аннотированных схем с числами
и подписями: Mermaid их теряет.

Все ASCII-диаграммы помечаются ` ```text ` (§2.1).

## 7. Что решено не делать

| Приём | Почему нет |
| --- | --- |
| GFM-алерты `> [!NOTE]` | не рендерятся в превью VS Code |
| Сноски `[^1]` | не рендерятся в превью VS Code |
| `:::note` / `:::tip` | не рендерятся нигде |
| Frontmatter | превью VS Code показывает его как текст |
| Ручной TOC внутри главы | дублирует навигацию сайта и Outline, устаревает при первой правке заголовка |
| Строки схем шире 80 символов | ломаются переносом |
| Разметка «только для сайта» | текст обязан читаться и в исходнике |

## 8. Что проверяет линтер

```bash
npm run lint          # весь репозиторий
npm run lint -- --report       # отчёт без ненулевого кода возврата
```

| Правило | Что ищет |
| --- | --- |
| `fence-untagged` | безымянный ` ``` ` |
| `fence-unknown-tag` | тег вне списка `text` / `bash` |
| `fence-meta` | метаданные у открывающего фенса |
| `fence-in-quote` | блок кода внутри `>` |
| `fence-indented` | блок кода внутри элемента списка |
| `fence-unclosed` | незакрытый блок |
| `fence-wide` | строка блока `text` шире 80 символов |
| `emoji` | эмодзи вне разрешённого набора |
| `marks` | ✓ ✗ ● ◆ и родственники |
| `link-broken` | относительная ссылка на несуществующий файл |
| `footer-missing` | у главы нет подвала навигации |
| `details-blank-line` | `<details>` без пустых строк вокруг содержимого |
| `frontmatter` | YAML-frontmatter в начале файла |

Ссылки на главы, объявленные в `README.md`, но ещё не написанные,
считаются запланированными и находкой не являются: они печатаются
отдельной строкой в сводке.

Не проверяются `CONVENTIONS.md` и `system/`: там внутри блоков лежат
тексты промтов и примеры запрещённых форм, и они обязаны оставаться
дословными.

## 9. Как книга превращается в сайт

Сайт не хранит текст. Он читает те же файлы и раскрашивает их при
сборке. Отсюда несколько форм, которые нельзя ломать «для красоты».

| Что в файле | Во что превращается на сайте |
| --- | --- |
| Оглавление в `README.md` | Левая колонка, обложка, порядок глав, кнопки «предыдущая / следующая» |
| Строки `` `Уровень: L2` `` под заголовком | Шапка главы: уровень, блок, риск, ссылки на нужные главы |
| `## Название раздела` | Раздел с цветной меткой; красная у «Безопасности» и «Цены ошибки», зелёная у «Проверки» и «Практики» |
| `[ПРОВЕРЬ TDS]`, `[СПОРНО]`, `[НЕ ОБЕЩАЙ КЛИЕНТУ]` | Цветные плашки в тексте |
| Абзац, начинающийся с ⚠️ | Плашка предупреждения |
| Ссылка на ненаписанную главу | Не ссылка, а пометка «скоро»: читатель не попадает в пустоту |
| Подвал навигации главы | Убирается: его заменяют кнопки внизу страницы |
| `---` между разделами | Убирается: разделы уже разделены вёрсткой |
| ` ```text ` со схемой | Моноширинный блок с горизонтальной прокруткой |

Что из этого следует для того, кто пишет главы:

- **Строка главы в оглавлении `README.md` имеет значение.** Формат
  `| 9 | [Название](chapters/09-equipment.md) | ⬜ |`. Пока стоит ⬜,
  глава не открывается и все ссылки на неё показываются как «скоро».
  Меняете ⬜ на ✅ — глава появляется на сайте.
- **Названия разделов берутся из списка** мастер-промта
  ([prompts.md §1](system/prompts.md)). Придуманное своё название
  отрисуется, но без цветной метки.
- **Ничего не нужно делать руками для сайта.** Ни адресов страниц,
  ни оглавления внутри главы, ни картинок-заголовков.

Посмотреть, как глава выглядит на сайте, до публикации:

```bash
npm run dev
```

Проверка перед публикацией — линтер и сборка:

```bash
npm run lint
npm run build
```
