Ты пишешь главу книги «Детейлинг: от новичка до владельца студии».
Роль, аудитория, принципы и запреты — в мастер-промте
`system/prompts.md` §1. Он для тебя обязателен целиком.

# Что прочитать перед началом

Именно в этом порядке, ничего не пропуская:

1. `system/prompts.md` §1 (мастер-промт) и §2 (промт написания главы).
   Найди границы разделов: `grep -n '^## ' system/prompts.md`, затем
   Read с offset/limit. Целиком файл не читай — в нём есть промты,
   которые тебе не нужны.
2. `CONVENTIONS.md` целиком: это правила оформления, их нарушение
   ломает страницу на сайте.
3. Строку главы в `README.md` — номер, точное название, часть, уровень.
4. Раздел «Итоги главы» предыдущей главы:
   `awk '/^## Итоги главы/,0' chapters/NN-*.md`. Оттуда берутся
   введённые термины, разобранные мифы и обещания «разберём позже»,
   адресованные твоей главе. Все обещания, адресованные ей, обязаны
   быть закрыты.
5. Заголовки соседних глав, чтобы не объяснять чужой материал:
   `grep -n '^## ' chapters/*.md`.

Полные тексты чужих глав не читай — только заголовки и «Итоги».
Глава весит 40–60 КБ, три прочитанных главы съедают окно.

# Как устроена глава

- Шапка: `# NN. Название`, под ней четыре строки в обратных кавычках
  (`Уровень:`, `Блок:`, `Риск ошибки:`, `Предполагает знание глав:`),
  затем `---`. Смотри `head -8 chapters/08-shop-and-water.md`.
- Разделы `##` — в порядке из мастер-промта, блок «ОБЯЗАТЕЛЬНАЯ
  СТРУКТУРА ГЛАВЫ». Обязательные пишутся всегда; необязательный
  раздел пишется, только если есть материал. Раздел короче пяти
  строк вреднее отсутствующего.
- Последняя строка файла — подвал навигации:
  `[← 7. Название](07-safety.md) · [Оглавление](../README.md) · [9. Название →](09-equipment.md)`
  Правая ссылка ставится только на существующий файл.
- Объём: обычная глава 6000–8000 слов; ключевые (17, 20, 22, 25, 28,
  30, 42) 9000–12000; обзорные (1, 9, 27, 33) 5000–6500. Под форму
  главы не выравнивают.

# Порядок работы

1. Собери каркас: какие разделы будут в этой главе и о чём каждый.
   Держи в голове, что объём набирается семью жанрами из §1, а не
   пересказом.
2. Пиши файл `chapters/NN-slug.md` в три-четыре подхода, иначе ответ
   обрежется на середине главы. Первый — Write с шапкой и разделами
   до «Разбора брака». Дальше — Edit: в `old_string` бери последние
   две-три строки файла, в `new_string` — их же плюс новый кусок.
   Так текст главы ни разу не проходит через контекст целиком.
3. Дай главе разбор брака на 900–1500 слов: обычный случай, машина
   с замерами, шаг отказа, цена в часах и рублях, три предотвращающих
   правила, разговор с клиентом после случая. Это раздел, ради
   которого главу читает опытный мастер.
4. Проверь обязательный минимум врезок: одна «Откуда цифра», две
   «Пример», одна «Для новичка», одна «Для опытного». Слово в начале
   врезки пишется точно как в `CONVENTIONS.md` §4, с точкой, иначе
   сайт её не отрисует.
5. Проведи через главу сквозную машину книги хотя бы в одном примере
   (чёрный седан D-класса 2019 года, 140 000 км, ЛКП 105–125 мкм,
   мягкий лак, перекрашенное правое переднее крыло 185–200 мкм).
6. Поставь `![Подпись](/img/NN-имя.jpg)` только там, где текстом
   научить нельзя. Файлов в `public/img/` пока нет, поэтому линтер
   поймает такую строку как `image-missing` — не ставь изображение
   в файл, а вынеси нужные кадры списком в свой отчёт.
7. Обнови `README.md`: в строке главы ⬜ → ✅. Это и есть публикация:
   пока стоит ⬜, страницы на сайте нет.
8. Допиши правую ссылку в подвал предыдущей главы.

# Самопроверка перед сдачей

Пройди список §2 промта («Перед выдачей проверь себя») и отдельно:

- каждая цифра — диапазон с условием, а не абсолютное число;
- составы названы классами (`щелочная пена pH 11–13`), а не брендами;
- термин определён при первом появлении, одной фразой, в том же
  абзаце;
- ни одного слова из чужих ремёсел: жаргон программистов,
  маркетологов и методистов запрещён, аналогии — из быта, кухни,
  стройки, медицины, автосервиса;
- одна мысль объяснена в одном месте; «Правила мастера» и «Так делать
  нельзя» — сводки строкой, а не пересказ разделов выше;
- нет двух таблиц подряд без текста между ними и таблиц шире пяти
  колонок; механизм объяснён текстом, таблица рядом — сводка.

Затем обязательно:

```bash
npm run lint
npm run build
```

Линтер должен дать ноль находок, сборка — пройти. Если что-то не так,
чини сам и прогоняй заново. Коммит не делай: это решение автора.

# Что вернуть

Отчёт на 15–25 строк, без текста главы:

- номер, название, файл, объём в словах (`wc -w`);
- какие разделы написаны и какие обязательные сознательно пропущены,
  с причиной;
- какие обещания предыдущих глав закрыты;
- какие термины введены и какие обещания «разберём позже» оставлены
  следующим главам (это уйдёт в «Итоги»);
- список нужных фотографий: имя файла и что на кадре;
- результат `npm run lint` и `npm run build`;
- спорные места, где нужно решение автора.
