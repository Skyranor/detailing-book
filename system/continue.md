# Хендофф: как продолжить книгу про детейлинг в новом чате

Рабочий файл. Он и [prompts.md](prompts.md) — всё, что нужно, чтобы
продолжить книгу без пересказа предыстории.

## 1. Что вставить в новый чат

```text
Продолжаем книгу «Детейлинг: от новичка до владельца студии»
(корень репозитория). Прочитай:
  CONVENTIONS.md
  README.md
  system/prompts.md
  system/continue.md
  последнюю написанную главу целиком
  раздел «Итоги главы» предыдущей главы

Работай по промту написания главы (prompts.md §2), оформление —
CONVENTIONS.md плюс prompts.md §9. Книга читается на сайте: приём
оценивается по виду страницы, в том числе на телефоне.

Перед коммитом:
  npm run lint      оформление, должно быть 0 находок
  npm run build     сборка сайта книги, должна пройти без ошибок
```

## 3. Порядок работы над главой

1. Взять номер и название из README.
2. Взять «Итоги главы» предыдущей: термины, мифы, обещания «разберём позже».
3. Написать главу по обязательной структуре (prompts.md §1, блок
   «ОБЯЗАТЕЛЬНАЯ СТРУКТУРА ГЛАВЫ»).
4. Проверить, что закрыты обещания из «Итогов», адресованные этой главе.
5. Обновить статус главы в README (⬜ → ✅). Это и открывает главу
   на сайте: пока стоит ⬜, страницы нет, а ссылки на неё показываются
   как «скоро».
6. Поставить подвал навигации новой главе и дописать правую ссылку
   в подвал предыдущей ([CONVENTIONS §5](../CONVENTIONS.md)).
7. Прогнать линтер: `npm run lint`, добиться нуля находок.
8. Собрать сайт: `npm run build`. Посмотреть главу вживую: `npm run dev`.
9. Коммит: одна глава — один коммит, сообщение на русском. После
   отправки в GitHub сайт на Vercel пересобирается сам.

Шаги 2–8 можно раздать агентам: `continuity-keeper` собирает термины
и обещания, `chapter-writer` пишет главу, `chapter-checker` закрывает
проверки. Кого звать и в каком порядке — [agents.md](agents.md).

## 4. Правила, которые ломаются чаще всего

| Правило | Как ломается | Как проверить |
| --- | --- | --- |
| Цифра без условия | «полируй на 1500 об/мин» вместо диапазона с условием | Поиск по числам в тексте: у каждого должен быть диапазон и «при каком» |
| Бренд вместо класса состава | «возьми состав X» вместо «щелочная пена pH 11–13» | Проверочный вопрос prompts.md §8.4 |
| Пропущенная безопасность | Есть химия или пыль, нет раздела «Безопасность» | Раздел обязателен во всех главах, где это есть |
| Термин раньше определения | «деконтаминация» в главе 1 без пояснения | Сверка с «Итогами» предыдущих глав |
| Обещание результата | «уберём все царапины» | Раздел «Что нельзя обещать клиенту» обязателен там, где физика ограничивает |
| Ссылка текстом, а не ссылкой | «см. главу 18» | Формат `[главе 18](18-machines.md)`, [CONVENTIONS §7](../CONVENTIONS.md) |
| Подвал главы | Забыт совсем или ведёт на ненаписанную главу | Линтер ловит как `footer-missing` и `link-broken` |
| Одна мысль в четырёх разделах | «Не три въевшееся тряпкой» разобрано и в «Цене ошибки», и в «Мифах», и в «Правилах мастера» | Объяснение — в одном месте, в сводках только строка |
| Механизм зажат в ячейку таблицы | Причина дефекта описана двенадцатью словами в колонке «Механизм» | Текст плюс таблица-сводка рядом |
| Нет разбора брака | Глава написана, раздела «Разбор брака» нет | Раздел обязателен в каждой главе (prompts.md §1, жанр 1) |
| Врезка не отрисовалась | Написано `**Примеры.**` вместо `**Пример.**` | Линтер ловит как `callout-unknown` |

## 5. Как книга читается

Одно место: [detailing-book.vercel.app](https://detailing-book.vercel.app).
Оглавление слева, разделы главы справа, поиск, светлая и тёмная темы.
Файлы в репозитории — исходник, а не способ чтения; отрисовка в GitHub
и в превью редактора решений не определяет.

Сайт **не хранит текст**: он читает `README.md` и `chapters/*.md` при
сборке. Что именно он делает с разметкой и какие формы записи нельзя
ломать — [CONVENTIONS §11](../CONVENTIONS.md).

Отсюда два практических следствия. Первое: форма, которую сайт не
разбирает (алерты, сноски, контейнеры, frontmatter, Mermaid), выйдет
на страницу сырым текстом — она запрещена. Второе: телефон. Схема
шире 80 символов и таблица шире пяти колонок ломаются именно там,
поэтому главу перед коммитом смотрят в узком окне.

Публикация: репозиторий подключён к Vercel, страницы статические.
Отправили коммит в GitHub — сайт пересобрался.

по главе за коммит. Глава 1 расширена: 3938 → 7242 слова.

и причина» из четырёх симптомов, «Разговор с клиентом» диалогом,
